## 1. 快速上手

| 项 | 值 |
|---|---|
| 前端地址 | `http://localhost:5173` |
| API 文档 | `http://localhost:8000/docs` |
| 健康检查 | `http://localhost:8000/api/v1/health` |
| 后端端口 | 8000 |
| 数据库 | SQLite (`annto.db`) / PostgreSQL |

### 一键启动

```bash
# 后端
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 前端
cd frontend
npm install
npm run dev

# 或用 Docker
docker-compose up -d
```

## 2. 工单处理全流程

```
创建工单(待处理)
    ↓
执行 Agent(处理中)
    ↓
Agent 链路完成(待审核)
    ↓
人工授权 → 通过/驳回/修改后通过
```

---

## 3. 创建工单

在工单列表页点击"新建工单"，填写表单：

| 字段 | 必填 | 说明 |
|------|------|------|
| 客户名称 | ✅ | 收/发货方名称 |
| 运单号 | | 物流运单编号 |
| 发件人 | | 发货方 |
| 收件人 | | 收货方 |
| 目的地 | | 送达地址 |
| 问题描述 | ✅ | 咨询/投诉/异常详情 |
| 货值(元) | | 货物申报价值 |

提交后工单状态变为**待处理**。

---

## 4. 执行 Agent 链路

在工单列表点击"执行 Agent"，系统自动执行 6 个 Agent：

| 顺序 | Agent | 功能 | 预期输出 |
|------|-------|------|---------|
| 1 | 订单查询 | 查询物流订单状态 | 运单号、当前位置、预计到达 |
| 2 | 单据录入 | 识别运单/回单 | 运单号、货物描述、总重量 |
| 3 | 财务对账 | 发票 vs 实收比对 | 差异额、对账状态 |
| 4 | 调度校验 | 检查库存/车辆/路线 | 建议车型、预计配送天数 |
| 5 | 风控检测 | 地址/收件人/货物核实 | 风险评分、风控建议 |
| 6 | 结论汇总 | 聚合全链路输出 | 汇总报告、操作建议 |

执行完成后状态变为**待审核**。

---

## 5. 查看 Agent 追溯

在工单详情页可查看完整的 Agent 执行链路，包括：
- 每个 Agent 的状态（✅ 完成 / ❌ 失败 / ⏳ 运行中）
- 输入输出数据（JSON 格式可展开）
- 置信度评分（百分比）
- 执行耗时（毫秒）

---

## 6. 人工授权

状态为"待审核"的工单，在详情页点击"进入人工授权"：

1. 查看 **AI 建议摘要**：案件信息 + 理算金额 + 风险等级
2. 查看 **Agent 处理摘要**：6 个 Agent 的结论速览
3. 查看 **全链路追溯**：每个 Agent 的详情可下钻
4. 选择操作：

| 操作 | 说明 | 用途 |
|------|------|------|
| ✅ 通过 | 确认 AI 建议 | 常规通过 |
| ❌ 驳回 | 填写驳回理由 | 信息有误/不符合条件 |
| ✏️ 修改后通过 | 修改金额后确认 | AI 理算不准确时 |

5. 输入**操作人姓名**（必填，记入审计日志）
6. 提交

> ⚠ 此操作不可撤回，请确认 AI 推理结果后再执行。

## 8. API 速查

### 创建工单
```bash
curl -X POST http://localhost:8000/api/v1/tickets \
  -H "Content-Type: application/json" \
  -d '{"insured_name":"上海华联","insurance_product":"物流运输",\
       "incident_desc":"配送延迟","incident_date":"2026-07-24",\
       "order_no":"ORD-001","sender":"佛山美的","receiver":"上海华联"}'
```
预期返回：`{"id": 1, "case_no": "CL202607240001", "status": "draft", ...}`

### 执行 Agent
```bash
curl -X POST http://localhost:8000/api/v1/tickets/1/run
```
预期返回：`{"message": "Agent 链路执行完成", "case": {...}}`

### 查看追溯
```bash
curl http://localhost:8000/api/v1/tickets/1/traces
```
预期返回：`[{"agent_label": "订单查询", "status": "completed", "confidence": 0.96, ...}, ...]`（6 条）

### 人工审核
```bash
curl -X POST http://localhost:8000/api/v1/tickets/1/review \
  -H "Content-Type: application/json" \
  -d '{"action":"approve","comment":"同意赔付","operator":"测试员"}'
```
预期返回：`{"action": "approve", "operator": "测试员", ...}`

### 健康检查
```bash
curl http://localhost:8000/api/v1/health
```
预期返回：`{"status": "ok", "service": "annto A2A 智能客服平台", "env": "development"}`

## 9. 常见问题排查

**Q: 前端页面打不开？**
A: 确认后端已启动（`curl http://localhost:8000/api/v1/health`）。前端代理需要后端运行在 8000 端口。

**Q: Agent 执行失败？**
A: 检查后端日志 `backend/data/logs/app.log`。mock 模式通常不会失败，如失败检查数据库连接。

**Q: 工单状态不对？**
A: 已审核的工单不能再次执行 Agent 或审核。需新建工单。

**Q: 如何重置测试数据？**
A: 删除 `backend/annto.db` 文件重启即可。

**Q: API 返回 401？**
A: 需要在请求头加 `X-API-Key`，或配置 `ANNTO_API_KEY=` 为空跳过认证。

**Q: 认证配置在哪？**
A: `.env` 文件中 `ANNTO_API_KEY=your_key`。留空则不认证。
