## 二、P1 场景缺口与重构

### 2.1 同步编排 → 异步任务队列

**问题**: `run_chain()` 在 HTTP 请求线程中同步执行 6 个 Agent。
- 1 个 Agent 调用 LLM 耗时 3s，6 个串行 = 18s
- 10 个并发请求即耗尽 uvicorn worker
- HTTP 超时导致客户端 502，但 Agent 仍在后台运行

**重构方案**:
```
当前: POST /run → 同步执行 → 等待 → 返回结果
目标: POST /run → 返回 task_id (202) → 后台执行 → GET /status 轮询
```

```python
# 目标代码结构
@app.post("/{id}/run", status_code=202)
async def run_agents(id: int, background_tasks: BackgroundTasks):
    background_tasks.add_task(orchestrator.run_chain, id)
    return {"task_id": id, "status": "processing"}

@app.get("/{id}/status")
def get_status(id: int):
    case = db.query(Case).filter(Case.id == id).first()
    return {"status": case.status.value, "progress": "3/6" if ... else "6/6"}
```

### 2.2 Agent 并行化

C Agent（财务对账）和 D Agent（调度校验）无数据依赖，可并行执行。

```python
# orchestrator.py 当前串行
self._run_serial([C, D], ...)  # 6s + 4s = 10s

# 目标：并行
with ThreadPoolExecutor(max_workers=2) as executor:
    future_c = executor.submit(agent_c.process, ...)
    future_d = executor.submit(agent_d.process, ...)
    result_c = future_c.result()  # 6s
    result_d = future_d.result()  # 4s (wait 6s total)
```

并行后链路耗时：A(1s) + B(1s) + max(C(6s),D(4s)) + E(2s) + F(1s) = 11s（串行 15s）。

### 2.3 状态机缺陷

**当前**: Agent 失败回滚到 DRAFT。如果并发重试，DRAFT 被认为是"新案件"。

**改进**: 增加 FAILED 状态
- DRAFT → PROCESSING → PENDING_REVIEW → APPROVED|REJECTED
- PROCESSING → FAILED → PROCESSING (重试)

## 三、P2 场景缺口与重构

### 3.1 缺少图像预处理

当前管线：上传 → OCR → 分类 → 提取

真实场景需要：上传 → **倾斜校正** → **二值化** → **去噪** → OCR → 分类 → 提取

```python
# 需要增加的图像预处理管线
class ImagePreprocessor:
    def process(self, image: np.ndarray) -> np.ndarray:
        image = self.deskew(image)      # 倾斜校正
        image = self.binarize(image)    # 二值化（大津法）
        image = self.denoise(image)     # 去噪（中值滤波）
        return image
```

### 3.2 缺少 LLM 分类回退

当前分类器：关键词匹配（5 类，正确率约 70%）

目标：双路分类器
```
关键词分类 → 置信度 > 0.85 → 直接输出
           → 置信度 0.5-0.85 → LLM 二次确认
           → 置信度 < 0.5 → 返回 "不确定" + top-3 候选
```

### 3.3 缺少置信度校准

当前：直接输出置信度数字，无校准
目标：引入边际分析 + 历史校准

### 3.4 缺少持久化

每个请求无状态，解析结果不保存。需增加：
- PostgreSQL 表 `parsed_documents`
- GET /documents/{id} 查询历史
- 支持批量导入（CSV/Excel）
