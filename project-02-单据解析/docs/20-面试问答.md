# 面试高频问题 — 多模态物流单据解析引擎

## Q1：为什么选择自研管线架构而不是用现成的文档解析服务？

**风险**：自研管线开发周期长，初期效果可能不如成熟商业服务。

**我们的方案**：不排斥商业服务，而是采用**可插拔 OCR 引擎**架构：

| 方案 | 中文识别率 | 私有化部署 | 自定义训练 | 成本 | 结论 |
|------|-----------|-----------|-----------|------|------|
| PaddleOCR | 98.5% | ✅ | ✅ | 免费 | **生产首选** |
| Tesseract 5 | 85% | ✅ | ✅ | 免费 | 备选 |
| 阿里云OCR | 99% | ❌ | ❌ | 按量计费 | SaaS 场景补充 |

**核心决策**：MVP 用 mock 占位，生产用 PaddleOCR（私有化部署满足安得内网需求 + 可针对物流单据自定义训练）。

**架构优势**：`OCREngine` 通过 `provider` 参数切换，业务代码零改动。

```python
class OCREngine:
    def __init__(self, provider: str = "mock"):
        self.provider = provider
        # 生产环境: provider="paddleocr" | "aliyun"
```

## Q2：5 类文档类型够吗？安得有 21 个垂直行业，单据格式差异怎么处理？

**风险**：分类粒度太粗，实际场景覆盖不全。

**设计方案**：采用**双路分类 + 行业扩展**策略。

1. **基础 5 类**（运单/回单/仓储单/发票/证件）覆盖 80% 通用场景
2. **21 行业扩展**通过 `industry_hint` 参数注入行业特定关键词加权：

```python
INDUSTRY_PREFIXES = {
    "appliance": ["家电", "空调", "冰箱", "洗衣机", "电视"],
    "fmcg": ["快消", "食品", "饮料", "日化"],
    "auto": ["汽车", "零部件", "轮胎", "发动机"],
}
```

3. **LLM 回退**：关键词置信度 < 0.85 时触发 DeepSeek 二次确认

**未来的模板仓库**：每接入一个新行业客户，在模板仓库中新增一套字段映射规则。

## Q3：置信度计算公式为什么从加权平均改为边际分析？

**风险**：旧公式 `ocr*0.3 + cls*0.3 + avg_field*0.4` 无法区分"模棱两可"和"确定无疑"。

**问题分析**：
- 场景 A（高一致）：字段 [0.98, 0.97, 0.99] → 加权 0.97 ✅
- 场景 B（低一致）：字段 [0.60, 0.55, 0.98] → 加权 0.83 ❌（应更低）

**改进方案**：引入边际分析

```
final = raw * (0.7 + 0.3 * min(margin, 1.0))
margin = (best_field_conf - second_best_field_conf) / best_field_conf
```

**决策阈值**：
| 校准后置信度 | 动作 |
|-------------|------|
| > 0.85 | 自动处理 |
| 0.60 ~ 0.85 | 人工抽检 |
| < 0.60 | 强制人工 |

## Q4：图像预处理为什么重要？当前为什么没做？

**业务场景**：司机用手机拍摄单据，普遍存在倾斜/光照不均/模糊问题。

**现状**：MVP 跳过了预处理阶段，直接 OCR。真实数据上准确率会下降 15~20%。

**计划**（Phase 2）：插入 ImagePreprocessor 管线。

```python
class ImagePreprocessor:
    def process(self, image: np.ndarray) -> np.ndarray:
        image = self.deskew(image)      # 倾斜校正
        image = self.binarize(image)    # 二值化
        image = self.denoise(image)     # 去噪
        return image
```

## Q6：如何保证 OCR/LLM 的准确性？

**多层保障**：
1. **置信度校准**：边际分析自动标记低质量结果
2. **双路分类**：关键词 + LLM 双重确认
3. **纠错闭环**（计划中）：人工修正 → 增量训练 → A/B 测试上线
