## 二、P1 — A2A 智能客服平台

### 2.1 架构模式

分层 + 事件驱动 + A2A Agent 协同

| 层 | 职责 | 技术 |
|----|------|------|
| 接入层 | HTTP 路由、认证、限流 | FastAPI + JWT |
| 编排层 | Agent 链路调度、状态管理 | AgentOrchestrator + Celery |
| Agent 层 | 业务逻辑处理 | 6 个独立 Agent |
| 协议层 | Agent 间通信 | A2AMessage (dataclass) |
| 事件层 | 跨 Agent 通知 | Redis Streams |
| 持久层 | 数据存储 | PostgreSQL + SQLAlchemy |
| 可观测层 | 日志/指标/追踪 | loguru + Prometheus + OpenTelemetry |

### 2.2 Agent 链设计

```
串行段 A(订单查询) → B(单据录入)
                ↓
并行段 C(财务对账) ‖ D(调度校验)  ← feature_agent_parallel=true
                ↓
串行段 E(风控检测) → F(结论汇总)
                ↓
          人工授权 Gate
```

## 三、P2 — 多模态物流单据解析引擎

### 3.1 架构模式

管线架构（Pipeline Architecture）

```
输入(拍照/扫描/PDF)
  → 图像预处理(倾斜校正/二值化/去噪)       ← ❌ 当前缺失
    → 文档分类(关键词/LLM 双路)            ← ⚠️ 仅关键词
      → OCR 文字提取(PaddleOCR)           ← ⚠️ 当前 mock
        → 字段提取(按类型模板)              ← ⚠️ 硬编码
          → 逻辑校验(跨字段一致性)          ← ❌ 缺失
            → 置信度校准(边际分析)          ← ❌ 缺失
              → 输出结构化 JSON
```

### 3.2 置信度策略

当前公式存在缺陷：`ocr_conf*0.3 + cls_conf*0.3 + avg(field_conf)*0.4`

改进方案：引入边际分析
```
final_confidence = (best_conf - second_best_conf) / best_conf
if final_confidence > 0.3 → 自动处理
elif final_confidence > 0.15 → 人工抽检
else → 强制人工
```
