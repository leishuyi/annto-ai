# 面试高频问题 — 供应链智能决策助手

## Q1：你们的"智能"决策助手和普通报表查询有什么区别？

**设计方案**：三层架构，逐步递进智能程度：

```
第一层：Agentic Reasoning
  用户问题 → 意图分类 → 子查询分解 → Agent 查询 → LLM 综合 → 建议

第二层：运筹优化（规划中）
  OR-Tools 约束求解 → 多仓串提 → 动态路径优化

第三层：仿真推演（规划中）
  假设场景 → 蒙特卡洛模拟 → 影响评估 → 报告
```

**和普通报表的区别**：
| 维度 | 普通报表 | 决策助手 |
|------|---------|---------|
| 输入 | SQL/固定筛选 | **自然语言** |
| 输出 | 数据表格 | **建议+推理** |
| 分析 | 人工判断 | **AI 辅助决策** |
| 仿真 | 无 | **What-if 推演** |

## Q2：NL2SQL 只有 4 个 if-else，这能叫智能吗？

**阶段性策略**：
| 阶段 | 实现 | 准确率 | 阶段 |
|------|------|--------|------|
| Phase 0 | 4 个 if-else 关键词匹配 | ~40% | **当前（Mock）** |
| Phase 1 | DeepSeek API + Schema Linking | ~80% | 计划 |
| Phase 2 | 动态 Few-Shot + 自修正 | ~90% | 计划 |

**真正的 NL2SQL 架构已在 llm_optimizer.py 中设计完成**：
```python
class NL2SQLEngine:
    def generate_prompt(self, question: str) -> str:
        # DB Schema 作为固定前缀 → DeepSeek Prefix Cache
        return f"{DB_SCHEMA}\n将问题转为 SQL：{question}"
```

## Q4：多路径推理（Self-Consistency）在实际中有效吗？

**场景验证**："华东区空调还有多少库存？"

| 路径 | Temperature | 回答 |
|------|------------|------|
| 路径 1 | 0.3 | 华东区空调库存 2500 台 |
| 路径 2 | 0.5 | 华东仓现有空调 2500 台 |
| 路径 3 | 0.7 | 华东区合计可用 3000 台（库存+在途）|

**投票结果**：3 条路径答案一致（2500 台库存），置信度 100%。分歧时自动降低置信度，提醒人工介入。

## Q5：CAG 和 RAG 比有哪些优劣？

| 维度 | CAG | RAG |
|------|-----|-----|
| 延迟 | **低**（知识在 prefix cache）| 高（每轮检索+排序）|
| 知识更新 | **需重建缓存** | 实时更新 |
| 知识量 | **有限**（context window）| 理论上无限 |
| 复杂度 | **低** | 高（需检索系统）|

**我们的选择**：供应链知识（KPI/规则）相对固定，适合 CAG。历史数据查询用 NL2SQL。
