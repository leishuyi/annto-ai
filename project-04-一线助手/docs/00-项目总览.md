# annto 一线人员智能助手 — 项目文档

## 概述
双端设计：司机端（移动 APP）+ 运营端（Web 后台），覆盖配送全链路的智能化。

## 现状评估

**⚠️ 严重警告：当前为演示级别，各模块均为空壳，需逐个替换为真实 API。**

| 模块 | 当前状态 | 生产要求 |
|------|---------|---------|
| 导航 | 硬编码 1850km | 高德/百度 Maps API |
| 签收 | 永远成功 | PaddleOCR + 图像分类 |
| 话术 | 5 个 if-else | DeepSeek 情绪识别 |
| 上报 | 否定词检测 | ASR + NER 实体提取 |
| RPA | MD5 随机数 | 财务系统 API |
| 排班 | 3 个硬编码司机 | OR-Tools 运筹优化 |
| 预警 | 3 条静态数据 | 实时规则引擎 |

## 技术选型与方案对比

### 地图导航

| 方案 | 精度 | 物流优化 | 成本 | 结论 |
|------|------|---------|------|------|
| **高德 Maps API** ✅ | 高 | 货车路线 | 按量 | 物流行业主流 |
| 百度 Maps API | 高 | 货车路线 | 按量 | 备选 |
| OSRM 自建 | 中 | ❌ | 服务器 | 不推荐 |

### 签收核验

| 方案 | 签名识别 | 破损检测 | 结论 |
|------|---------|---------|------|
| **PaddleOCR** ✅ | 高 | 配合分类模型 | 可私有部署 |
| 阿里云 OCR | 最高 | ✅ | 按量计费 |
| 自研 CNN | 中 | 需标注数据 | 长期演进 |

### 排班优化

| 方案 | 求解质量 | 复杂度 | 结论 |
|------|---------|--------|------|
| **硬编码** ✅ | 无 | 零 | 当前演示 |
| OR-Tools (CP-SAT) | 最优解 | 中 | 生产目标 |
| 线性规划 (PuLP) | 最优解 | 中 | 备选 |
| 启发式算法 | 近似解 | 低 | 快速实现 |

### 财务对账

| 方案 | 准确性 | 实施成本 | 结论 |
|------|--------|---------|------|
| **MD5 mock** ✅ | 零 | 零 | 当前状态 |
| SAP API 对接 | 100% | 高 | 如安得用 SAP |
| 金蝶/用友 API | 100% | 中 | 备选 |
